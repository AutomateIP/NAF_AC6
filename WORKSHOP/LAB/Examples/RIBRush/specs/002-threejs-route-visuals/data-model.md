# Data Model: Three.js Route Feedback Visuals

The feature adds presentation state only. It does not change scenario data,
route evaluation, session state, scoring, or persistence.

## Decision Feedback Event

An immutable view of one completed player decision, created by the existing
game flow after route resolution.

| Field | Type | Meaning |
|---|---|---|
| `packetId` | string | Resolved packet identifier |
| `selectedNextHopId` | string | Next hop selected by the player |
| `selectedRouteIndex` | non-negative integer | Player's selected route position in the scenario |
| `winningRouteId` | string | Route selected by the existing evaluator |
| `winningRouteIndex` | non-negative integer | Correct route position in the scenario |
| `decisionStatus` | `correct \| wrong` | Result returned by the existing session resolver |
| `destination` | string | Packet destination shown in the challenge |
| `routes` | route display data[] | All candidate routers shown in the topology |
| `selectedRoute` | route display data | Selected route identity, label, prefix, and next-hop label |
| `winningRoute` | route display data | Winning route identity, label, prefix, and next-hop label |
| `ruleCode` | string | Existing evaluator rule code used in feedback |
| `explanation` | string | Existing accessible explanation text |

The event is consumed by the scene to depict the player's selected path and
the evaluator's winner. It is not input to the route evaluator and is not
stored after the feedback view is removed.

## Route Display Data

The minimum route details needed to label a visual router: route ID, next-hop
ID, next-hop label, network address, and prefix length. Any geometry or visual
arrangement is generated by the renderer and has no routing meaning.

## Packet Animation

A transient presentation state associated with a decision event:

- `event`: the immutable decision feedback event.
- `phase`: `ready`, `animating`, `settled`, or `unavailable`.
- `progress`: normalized animation progress when motion is enabled.

The selected path comes from `selectedRouteIndex` and the correct route comes
from `winningRouteIndex`; the scene MUST NOT evaluate route rules or derive
correctness from geometry or color. A timeout has no selected route and
remains on the existing 2D feedback path.

## Renderer Lifecycle

The renderer moves from `uninitialized` to `ready` or `unavailable`. It is
initialized lazily, then reused for feedback events during the run. Rendering
is idle when no feedback event is active. WebGL context loss transitions it to
`unavailable`, with the game and its 2D feedback remaining active. Renderer and
GPU resources are released on application teardown or permanent failure.
